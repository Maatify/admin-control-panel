# دليل بدء العمل — متوافق مع الواقع (Reality Aligned)

**المشروع:** لوحة تحكم الإدارة (Admin Control Panel)
**الحالة:** الوضع الحالي — Infrastructure-First
**التقنية:** PHP 8.2 (Slim Framework) + Twig + MySQL
**الجمهور المستهدف:** مطورو الـ Backend ومطورو الواجهة (Twig)

---

## 1️⃣ نظرة تنفيذية عامة

هذا المشروع هو **نظام إدارة إداري يعتمد على الـ Backend بشكل أساسي**
ومبني وفق مبدأ **Security-First / Zero-Trust**.

هذا **ليس** مشروعًا موجّهًا للواجهة أو للميزات السريعة.

### ما هو هذا المشروع؟

نظام إدارة مركزي مخصص لبيئات حساسة
(مالية، مؤسسية، أنظمة داخلية)، ويعتمد على:

* Zero-Trust (لا توجد ثقة ضمنية بعد تسجيل الدخول)
* سلسلة Middleware متعددة الطبقات
* سيطرة كاملة للخادم على الجلسات
* Step-Up Authentication للعمليات الحساسة
* تسجيل Audit إلزامي لكل العمليات الحرجة

### ⚠️ تحذير مهم

> أي تعديل يتم دون فهم كامل لهذا الملف
> يُعرّض النظام **لمخاطر أمنية عالية**.
>
> التعقيد الموجود في النظام **مقصود**.
> لا تحاول “تبسيطه” أو تجاوز آلياته.

  (`ADMIN_DB_HOST`, `ADMIN_DB_NAME`, `ADMIN_DB_USER`, `ADMIN_DB_PASS`)

  >
  > **مطورو الـ Backend:** استخدم مولد عشوائي آمن (CSPRNG)،
  > وارجع للفريق الأساسي/الأمني لتحديد الطول والصيغة الصحيحة.

  * أي بيانات تجريبية

### 📌 ملاحظة مهمة

* لن يوجد أي مستخدم Admin
* قاعدة بيانات فارغة **أمر متوقع وصحيح**

## 5️⃣ إنشاء أول Admin (Bootstrap) — **الأهم**

> ⚠️ هذه أهم خطوة في إعداد أي بيئة جديدة.

النظام **لا يحتوي** على واجهة ويب للتسجيل أو للتهيئة الأولى.

### الطريقة الوحيدة الصحيحة

#### 1️⃣ تشغيل سكربت التهيئة (CLI)

```bash
php scripts/bootstrap_admin.php
```

#### 2️⃣ اتباع التعليمات

1. السكربت يتحقق أنه لا يوجد أي Admin.
2. إدخال البريد الإلكتروني وكلمة المرور لأول Admin.
3. يتم توليد **TOTP Secret** وعرضه.
4. إعداد تطبيق المصادقة (Google Authenticator / Authy).
5. إدخال كود OTP للتحقق.
6. عند النجاح:

  * يتم إنشاء Admin
  * يتم اعتبار البريد الإلكتروني مُتحققًا منه

### ⚠️ تحذير أمني

> تشغيل هذا السكربت أكثر من مرة يُعد **مخالفة أمنية**.
> السكربت يتوقف تلقائيًا إذا وُجد أي Admin.
> يُمنع تمامًا محاولة تجاوز هذا السلوك.

## 7️⃣ المسارات المتاحة حاليًا

للحصول على القائمة الرسمية للمسارات المتاحة، يرجى الرجوع إلى:

1. **`docs/API.md`** — العقد الرسمي للـ API (Canonical Contract).
2. **`routes/web.php`** — التنفيذ العملي لتهيئة المسارات.

📌 **ملاحظة:** `docs/API.md` هو **المصدر الرسمي للحقيقة**. أي نقطة نهاية (Endpoint) غير موثقة فيه تعتبر غير متاحة، بغض النظر عما هو موجود في `routes/web.php`.

## 8️⃣ الواجهة و Twig — قواعد الاستخدام الآمن

### مكان القوالب

```
templates/
```

### قواعد صارمة

1. Controller ≠ View

2. ❌ ممنوع منطق أمني داخل Twig

3. يجب دائمًا الهروب (Escape):

   ```twig
   {{ value|e }}
   ```

4. استخدام مفاتيح الترجمة فقط

5. لا تفترض ترتيب أو وجود حقول DTO

### ملاحظات للواجهة

* **لا توجد واجهة تشغيل أولي:**
  الواجهة تفترض أن التهيئة (CLI) تمت بالفعل.
* **الحالة:**
  لا تفترض حالة معينة للنظام، وتعامل مع أخطاء 401/403 بشكل سليم.
